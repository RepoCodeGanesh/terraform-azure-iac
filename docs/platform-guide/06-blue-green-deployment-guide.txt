BLUE-GREEN DEPLOYMENT ARCHITECTURE OVERVIEW

The Blue-Green deployment strategy for TaxBot India ensures zero downtime, instant pings, pre-warming of database connections, and 1-click automated rollbacks across both backend and frontend layers.

BACKEND BLUE-GREEN STRATEGY (PYTHON FUNCTION APP)

1. Provision Deployment Slots:
   - Production Slot (Blue): Host func-ht-taxb-p-cin-01.azurewebsites.net
   - Staging Slot (Green): Host func-ht-taxb-p-cin-01-staging.azurewebsites.net

2. Deployment & Pre-warming Flow:
   - CI/CD packages Python code and deploys to staging slot.
   - Managed identity & Cosmos DB / Storage connections pre-warm without touching production.

3. Automated Slot Swap:
   - CI/CD pings /api/healthcheck on staging.
   - Upon success, executes: `az functionapp deployment slot swap --name func-ht-taxb-p-cin-01 --resource-group rg-ht-taxb-p-cin-01 --slot staging --target-slot production`
   - Traffic shifts 100% instantly with zero dropped HTTP requests.

FRONTEND BLUE-GREEN STRATEGY (AZURE STATIC WEB APP)

1. SWA Environment Isolation:
   - Production Environment (Blue): Serves live traffic at www.mytaxbot.site.
   - Staging Environment (Green): Serves preview builds at stapp-ht-taxb-p-cin-01-staging.azurestaticapps.net.

2. Global Atomic CDN Cutover:
   - React SPA bundle builds and deploys to SWA staging environment.
   - Automated browser smoke tests verify asset loading & APIM endpoint connectivity.
   - CI/CD promotes staging to production. Azure CDN performs an instant atomic cache purge across global edge nodes (<1 second cutover).

1-CLICK AUTOMATED ROLLBACK

If post-deployment health metrics degrade:
- Backend Rollback: Run `az functionapp deployment slot swap` to reverse production and staging slots in 3 seconds.
- Frontend Rollback: Select previous deployment ID in Azure DevOps or Azure Static Web App portal to revert CDN edge cache instantly.
