KNOWN ISSUES AND RESOLUTIONS (as of August 2026)

This document captures all known Terraform and pipeline issues encountered during deployment of the Azure AI Landing Zone, and their resolutions.

---

ISSUE 1: AVM Function App module deprecated azapi retry.multiplier warning

Symptom: Terraform plan/apply emits warning:
  "azapi: retry.multiplier is deprecated"

Cause: The Azure Verified Module (AVM) for web sites internally uses azapi with a deprecated attribute.

Status: Non-blocking. Does not prevent apply. Will be resolved in a future AVM module upgrade.
Resolution: No action needed. Monitor AVM module releases.

---

ISSUE 2: PrincipalNotFound during RBAC role assignment after Function App creation

Symptom: Terraform apply fails with:
  "PrincipalNotFound: Principal <objectId> does not exist in the directory"

Cause: System-Assigned Managed Identity takes 5-15 seconds to propagate in Microsoft Entra ID after Function App creation. RBAC assignment runs too quickly.

Resolution: Added resource "time_sleep" "wait_for_func_identity" with create_duration = "10s" and depends_on = [module.function_app]. All RBAC role assignments depend on this sleep resource.

---

ISSUE 3: Azure OpenAI SKU S0 not available in Central India

Symptom: Terraform apply fails:
  "The subscription does not have QuotaId/Feature required by SKU 'S0' from kind 'OpenAI'"

Resolution: Azure OpenAI account moved to East US (eastus) or Central India using GlobalStandard SKU. Variable openai_location_short changed from "sin" to "cin" (or "eus"). The naming module uses the openai_location_short variable separately from the main workload location.

---

ISSUE 4: VNet peering race condition — subnet update conflict

Symptom: Terraform apply fails intermittently:
  "AnotherOperationInProgress: Another operation is in progress on VNet..."

Cause: VNet peering module runs before the local VNet module finishes creating subnets.

Resolution: Added explicit depends_on = [module.aiast_vnet] to both VNet peering module calls (aiast_to_hub_peering and hub_to_aiast_peering).

---

ISSUE 5: Terraform outputs with sensitive AVM values causing plan errors

Symptom: Terraform plan fails with:
  "Output refers to sensitive values and must be marked sensitive"

Resolution: Any output that propagates sensitive values from AVM modules must be explicitly marked sensitive = true in outputs.tf.

Example fix:
  output "function_app_principal_id" {
    value     = module.function_app.system_assigned_mi_principal_id
    sensitive = true
  }

---

ISSUE 6: AVM Function App module — incorrect output attribute names

Symptom: Terraform apply fails referencing .name, .id, or .principal_id on the function_app module.

Cause: AVM modules expose outputs differently from raw azurerm resources.

Correct AVM output names:
  module.function_app.name                            (function app resource name)
  module.function_app.resource_uri                    (function app default hostname)
  module.function_app.system_assigned_mi_principal_id (managed identity object ID)

Do NOT use: .resource.name, .resource.id, .identity[0].principal_id

---

ISSUE 7: Storage account "storage_account_name" attribute deprecated

Symptom: Terraform plan warning:
  "storage_account_name" is deprecated in azurerm provider v4.x

Resolution: Replace storage_account_name with storage_account_id using the storage account resource ID.

Example:
  # DEPRECATED:
  storage_account_name = azurerm_storage_account.example.name

  # CORRECT (azurerm v4.x):
  storage_account_id = azurerm_storage_account.example.id

---

ISSUE 8: Static Web App — deployment_token invalid in pipeline

Symptom: Pipeline stage "Deploy to Static Web App" fails with:
  "deployment_token provided was invalid."

Cause: SWA_CLI_DEPLOYMENT_TOKEN pipeline variable is missing, stale, or was invalidated when Terraform recreated the Static Web App resource.

Resolution:
1. Fetch current token:
   az staticwebapp secrets list \
     --name stapp-ht-dvob-p-cin-01 \
     --resource-group rg-ht-dvob-p-cin-01 \
     --subscription f4ffefe1-d689-4059-969c-ccc73e2a11d4 \
     --query "properties.apiKey" -o tsv

2. Store in Key Vault:
   az keyvault secret set \
     --vault-name kv-ht-ss-p-cin-01 \
     --name SWA-CLI-DEPLOYMENT-TOKEN \
     --value "<token>" \
     --subscription 859a785c-bd38-402d-b595-1f44f40fb9bf

3. Pipeline fetches token at runtime from Key Vault (AzureCLI@2 step).
   Token is refreshed on every pipeline run — no stale variable.

ISSUE 9: Module azure.cosmos or azure.search.documents not found (VS Code)

Symptom: VS Code Pylance shows:
  "Cannot find module azure.cosmos"
  "Cannot find module azure.search.documents"

Cause: Python packages not installed in local development virtual environment. This is a local IDE tooling issue only — the packages ARE listed in requirements.txt and will be installed on the Azure Functions runtime.

Resolution: Install all dependencies locally:
  python -m venv .venv
  .venv\Scripts\activate
  pip install -r app/ai-assistant/backend/requirements.txt

DEBUGGING TIPS

1. Failed apply left resources outside state:
   Run: az resource list --resource-group rg-ht-dvob-p-cin-01 -o table
   Import any orphaned resources: terraform import <resource_address> <resource_id>

2. Check pipeline identity RBAC:
   az role assignment list --assignee <sp-object-id> --all -o table

3. Validate Terraform without backend:
   terraform init -backend=false && terraform validate

4. Check Function App logs:
   az functionapp logs tail --name func-ht-dvob-p-cin-01 --resource-group rg-ht-dvob-p-cin-01
