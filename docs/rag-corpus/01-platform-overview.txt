Title: Azure AI Landing Zone — Platform Overview
Source: docs/architecture.md

OVERVIEW

The Azure AI Landing Zone is an enterprise-grade, multi-subscription cloud platform provisioned using Terraform and Azure DevOps CI/CD pipelines. It follows the Microsoft Cloud Adoption Framework (CAF) Enterprise-Scale Landing Zone pattern and is designed to host AI workloads at near-zero idle cost.

SUBSCRIPTION TOPOLOGY

The platform uses four Azure subscriptions, each with a dedicated purpose and Azure DevOps Workload Identity Federation (WIF) service connection:

1. Bootstrap (7689ad81-71ba-481b-a17c-e1b6be61bab1)
   - Service connection: bootstrap
   - Purpose: Remote Terraform state storage account (sthtbootpcin01) and Key Vault (kv-ht-boot-p-cin-01)
   - All Terraform roots store their backend state here

2. Hub-prod (3eb8cc01-50c6-473e-8d5f-f8d532ae1f5b)
   - Service connection: hub-prod
   - Purpose: Central Hub VNet (vnet-ht-hub-p-cin-01), routing, firewall, bastion subnets

3. Shared-services (859a785c-bd38-402d-b595-1f44f40fb9bf)
   - Service connection: shared-services
   - Purpose: Log Analytics (law-ht-ss-p-cin-01), APIM Gateway (apim-ht-ss-p-cin-01), Private DNS Zones, Key Vault (kv-ht-ss-p-cin-01)

4. Apps-prod (f4ffefe1-d689-4059-969c-ccc73e2a11d4)
   - Service connection: app-prod
   - Purpose: AI Workloads — DevOnboard AI Assistant, Azure OpenAI, AI Search, Function App, Static Web App

NETWORK ARCHITECTURE (HUB AND SPOKE)

Hub Network (platform/hub): 10.0.0.0/16
  - AzureFirewallSubnet: 10.0.0.0/26
  - AzureBastionSubnet:  10.0.0.64/27
  - GatewaySubnet:       10.0.0.96/27

Spoke Network (workloads/ai-assistant): 10.40.0.0/16
  - AppSubnet:                10.40.1.0/24  (Function App VNet integration)
  - PrivateEndpointsSubnet:   10.40.2.0/24  (Private Link for OpenAI and Storage)

Hub-Spoke VNet peering is bi-directional and provisioned via module.aiast_to_hub_peering.

TERRAFORM STATE RULES

Each Terraform root has its own isolated state file stored in the bootstrap subscription:
- platform/bootstrap  → sthtbootpcin01/tfstate/bootstrap.tfstate
- platform/hub        → sthtbootpcin01/tfstate/hub.tfstate
- platform/shared-services → sthtbootpcin01/tfstate/shared-services.tfstate
- workloads/ai-assistant   → sthtbootpcin01/tfstate/ai-assistant.tfstate

All backend.hcl files use subscription_id = 7689ad81-71ba-481b-a17c-e1b6be61bab1 and use_azuread_auth = true (no storage keys).

DEPLOYMENT SEQUENCE

Deploy roots in this strict order to satisfy cross-root dependencies:
1. platform/bootstrap         — state backend and Key Vault
2. platform/hub               — hub VNet
3. platform/shared-services   — APIM, Log Analytics, DNS
4. workloads/ai-assistant     — spoke VNet, OpenAI, Function App (Terraform IaC)
5. app/ai-assistant           — React UI + Python backend (CI/CD pipeline)

CAF NAMING CONVENTION

Pattern: [resource-type]-[project]-[workload]-[environment]-[location-short]-[instance]

Examples:
  rg-ht-dvob-p-cin-01     (resource group, project=ht, workload=dvob, env=prod, region=centralindia)
  vnet-ht-hub-p-cin-01    (virtual network, hub workload)
  apim-ht-ss-p-cin-01     (API Management, shared-services workload)
  func-ht-dvob-p-cin-01   (Function App, ai-assistant workload)
  sthtbootpcin01           (storage account — hyphens omitted for DNS compatibility)

Location short codes:
  cin = Central India
  sin = South India
  eus = East US
