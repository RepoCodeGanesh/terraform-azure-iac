TERRAFORM REPOSITORY STRUCTURE

The repository is organized into platform layers (independent Terraform roots) and reusable modules:

terraform-azure-iac/
├── platform/
│   ├── bootstrap/        Layer 1 — Remote state storage account and Key Vault
│   ├── hub/              Layer 2 — Hub VNet, subnets, NSGs
│   └── shared-services/  Layer 3 — APIM, Log Analytics, Private DNS
├── workloads/
│   └── ai-assistant/     Layer 4 — AI workload spoke (OpenAI, Search, Functions)
├── modules/
│   ├── naming/           CAF naming helper — generates resource names from variables
│   ├── vnet/             VNet + subnet wrapper
│   └── vnet-peering/     Hub-spoke peering module
└── app/
    └── ai-assistant/
        ├── frontend/     React Chat UI (Vite, TypeScript)
        └── backend/      Python Azure Function (function_app.py)

PLATFORM/BOOTSTRAP

Provisions the foundation for all other layers:
- azurerm_resource_group — rg-ht-boot-p-cin-01
- azurerm_storage_account — sthtbootpcin01 (Standard_LRS) with blob container "tfstate"
- azurerm_key_vault — kv-ht-boot-p-cin-01 (Standard SKU, RBAC authorization model)

All other roots depend on this being deployed first.

PLATFORM/HUB

Provisions central networking:
- azurerm_resource_group — rg-ht-hub-p-cin-01
- module.hub_vnet — vnet-ht-hub-p-cin-01 (10.0.0.0/16) with subnets:
    AzureFirewallSubnet, AzureBastionSubnet, GatewaySubnet

PLATFORM/SHARED-SERVICES

Provisions shared platform services:
- azurerm_resource_group — rg-ht-ss-p-cin-01
- azurerm_log_analytics_workspace — law-ht-ss-p-cin-01 (PerGB2018, 30-day retention)
- azurerm_api_management — apim-ht-ss-p-cin-01 (Consumption_0 SKU — $0 base cost)
- azurerm_key_vault — kv-ht-ss-p-cin-01 (stores SWA deployment token)
- azurerm_private_dns_zone — for Key Vault, Storage, OpenAI, and Cosmos DB

BACKEND CONFIGURATION (backend.hcl)

Every Terraform root uses a backend.hcl file:

  resource_group_name  = "rg-ht-boot-p-cin-01"
  storage_account_name = "sthtbootpcin01"
  container_name       = "tfstate"
  key                  = "<root-name>.tfstate"
  subscription_id      = "7689ad81-71ba-481b-a17c-e1b6be61bab1"   # always bootstrap
  use_azuread_auth     = true

Initialize with: terraform init -backend-config=backend.hcl

PROVIDER ALIASING (CROSS-SUBSCRIPTION)

workloads/ai-assistant uses multiple provider aliases:
  provider "azurerm" { alias = "apps" }         — deploys to Apps-prod
  provider "azurerm" { alias = "hub" }           — reads Hub-prod VNet for peering
  provider "azurerm" { alias = "shared" }        — registers APIM backend in Shared-services

The app-prod service connection identity may need RBAC in Hub-prod and Shared-services for cross-subscription operations.

KEY TERRAFORM COMMANDS

  terraform init -backend-config=backend.hcl     # Initialize with remote backend
  terraform fmt -check -recursive                # Check formatting
  terraform validate                             # Validate configuration
  terraform plan -var-file=prod.tfvars -out=tfplan.bin
  terraform apply tfplan.bin

COST OPTIMIZATION RULES

Always default to these SKUs:
  API Management     → Consumption_0  ($0 base, pay-per-call)
  Azure Functions    → Consumption Y1 (1M free requests/month)
  AI Search          → Free F1        (50 MB, 3 indexes)
  Cosmos DB          → Free Tier      (1,000 RU/s + 25 GB)
  Static Web App     → Free Tier      (0.5 GB bandwidth)
  Storage Account    → Standard_LRS   (pennies/month)
  Log Analytics      → PerGB2018      (5 GB/month free ingestion)
