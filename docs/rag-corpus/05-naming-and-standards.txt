CAF NAMING CONVENTION

The platform uses the Microsoft Cloud Adoption Framework (CAF) standardized naming pattern:

  Pattern: [resource-type]-[project]-[workload]-[environment]-[location-short]-[instance]

Fields:
  resource-type    = Azure resource abbreviation (rg, vnet, kv, apim, func, etc.)
  project          = ht (project code for this repository)
  workload         = short workload identifier (boot=bootstrap, hub, ss=shared-services, dvob=DevOnboard)
  environment      = p (production), d (development), t (test)
  location-short   = cin (Central India), sin (South India), eus (East US)
  instance         = zero-padded sequence number (01, 02, ...)

RESOURCE TYPE ABBREVIATIONS

  rg      = Resource Group
  vnet    = Virtual Network
  snet    = Subnet
  nsg     = Network Security Group
  kv      = Key Vault
  st      = Storage Account (hyphens omitted for DNS: sthtbootpcin01)
  law     = Log Analytics Workspace
  apim    = API Management
  appi    = Application Insights
  func    = Function App
  asp     = App Service Plan
  stapp   = Static Web App
  oai     = Azure OpenAI
  srch    = AI Search (Azure Cognitive Search)
  cosmos  = Cosmos DB Account

MODULES/NAMING — CAF NAMING HELPER

The modules/naming Terraform module generates resource names from variables, ensuring naming consistency. Usage pattern in roots:

  module "aiast_rg_name" {
    source        = "../../modules/naming"
    resource_type = "resource_group"
    project       = var.project
    workload      = var.workload
    environment   = var.environment
    location      = var.location_short
    instance      = "01"
  }

  resource "azurerm_resource_group" "ai_assistant" {
    name     = module.aiast_rg_name.name   # → rg-ht-dvob-p-cin-01
    location = var.location
  }

ENVIRONMENT TAGS

All resources must include consistent tags for cost management:

  tags = {
    project     = "ht"
    workload    = "dvob"
    environment = "prod"
    managed_by  = "terraform"
  }

LOCATION STRATEGY

Primary platform region: Central India (centralindia / cin)
  - Resource groups, VNets, Function Apps, Storage, Cosmos DB, AI Search, Static Web App

Exception — Azure OpenAI:
  - Deployed in Central India (centralindia) using GlobalStandard SKU
  - If GlobalStandard unavailable in region, use eastus (eus) as fallback

COST SKU STANDARDS

The platform enforces these SKUs to maintain near-zero idle cost:

  Service                  SKU / Tier              Idle Monthly Cost
  -----------------------  ----------------------  -----------------
  API Management           Consumption_0           $0.00
  Azure Functions          Consumption Y1          $0.00
  AI Search                Free (F1)               $0.00
  Cosmos DB                Free Tier               $0.00
  Static Web App           Free Tier               $0.00
  Storage Account          Standard_LRS            < $0.01
  Log Analytics            PerGB2018               < $0.05
  Azure OpenAI             Pay-As-You-Go + TPM cap Pay per token

Never provision these without explicit approval:
  - APIM Developer or Standard tier
  - Azure AI Search Basic or Standard tier
  - Cosmos DB Provisioned Throughput > Free Tier
  - Azure OpenAI Provisioned Throughput
