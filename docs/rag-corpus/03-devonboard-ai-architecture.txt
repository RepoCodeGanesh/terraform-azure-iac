Title: DevOnboard AI Assistant — Application Architecture and API Reference
Source: docs/ai-assistant/DEVONBOARD_AI_PLAN.md

APPLICATION OVERVIEW

DevOnboard AI is an enterprise-grade, AI-powered onboarding and knowledge assistant for engineering teams. It answers questions about the Azure AI Landing Zone platform — including Terraform structure, subscription topology, CI/CD pipelines, naming conventions, and deployment procedures.

It uses Retrieval Augmented Generation (RAG): it retrieves relevant documentation chunks from Azure AI Search before calling Azure OpenAI, ensuring answers are grounded in authoritative platform documentation.

ARCHITECTURE FLOW

  User (Browser)
    └─► Azure Static Web App (stapp-ht-dvob-p-cin-01) — React UI
          └─► APIM Gateway (apim-ht-ss-p-cin-01) — rate limiting, caching
                └─► Python Function App (func-ht-dvob-p-cin-01)
                      ├─► Azure AI Search (srch-ht-dvob-p-cin-01) — RAG context retrieval
                      ├─► Azure OpenAI (oai-ht-dvob-p-cin-01) — gpt-4o-mini completion
                      └─► Cosmos DB (cosmos-ht-dvob-p-cin-01) — chat session history

BACKEND API — PYTHON AZURE FUNCTION

File: app/ai-assistant/backend/function_app.py
Runtime: Python 3.11, Azure Functions v2 programming model
Auth: System-Assigned Managed Identity + DefaultAzureCredential() — no API keys

Endpoints:
  POST /api/chat
    Request body:  { "message": "string", "session_id": "string (optional)" }
    Response body: { "reply": "string", "session_id": "string" }

  GET /api/health
    Response body: { "status": "healthy", "model": "gpt-4o-mini" }

STEP-BY-STEP REQUEST FLOW (POST /api/chat)

1. Parse JSON body → extract message and session_id (generate UUID if missing)
2. RAG retrieval → query Azure AI Search index "devonboard-docs" for top-4 relevant chunks
   - Tries semantic search first (query_type="semantic", configuration="default")
   - Falls back to simple keyword search if semantic not configured
   - Returns content, title, source fields
3. Session history → query Cosmos DB for last 6 messages (3 exchanges) for this session
4. Build prompt:
   - System prompt: DevOnboard AI persona + platform documentation context (from RAG)
   - History: prior conversation turns
   - User message: current question
5. Call Azure OpenAI gpt-4o-mini with max_tokens=1024, temperature=0.2
6. Persist user + assistant messages to Cosmos DB (upsert)
7. Return JSON response with reply and session_id

SECURITY (ZERO-TRUST / KEYLESS)

Authentication method:          DefaultAzureCredential()
Azure OpenAI access:            System-Assigned MI + "Cognitive Services OpenAI User" RBAC
AI Search access:               System-Assigned MI + "Search Index Data Reader" RBAC
Cosmos DB access:               System-Assigned MI + "Cosmos DB Built-in Data Contributor" RBAC
Storage access:                 System-Assigned MI + "Storage Blob Data Contributor" RBAC
No static keys or connection strings stored anywhere in code.

FRONTEND — REACT CHAT UI

Location: app/ai-assistant/frontend/
Framework: React + Vite + TypeScript
Deployed to: Azure Static Web App (stapp-ht-dvob-p-cin-01)
URL: https://stapp-ht-dvob-p-cin-01.azurestaticapps.net

Features:
- Dark-mode glassmorphic chat interface
- Session persistence via session_id
- Sends POST to APIM endpoint: https://apim-ht-ss-p-cin-01.azure-api.net/ai-assistant/chat
- Displays streaming-style reply rendering

CI/CD PIPELINE

Pipeline file: pipelines/azure-cicd-app-ai-assistant.yml
Stages:
  1. DeployFrontend — builds React UI, fetches SWA token from Key Vault, deploys to Static Web App
  2. DeployBackend  — installs Python deps, zips Function App, deploys via AzureFunctionApp@2
  3. ApimRegistration — imports OpenAPI spec into APIM, applies CORS policy

COSMOS DB SCHEMA (chat_history container)

Partition key: /sessionId

Document schema:
  {
    "id":        "uuid",
    "sessionId": "string",
    "role":      "user" | "assistant",
    "content":   "string",
    "timestamp": "ISO8601 UTC datetime"
  }

AI SEARCH INDEX SCHEMA (devonboard-docs)

Fields: id (key), content, title, source
Query types: semantic search (primary) + keyword fallback
Semantic configuration name: "default"
Data source: Azure Blob Storage container "documents" in sthtdvobpcin01
